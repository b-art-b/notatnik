# Testing strategy

Status: **draft** · Last updated: 2026-10-03

This document defines *how* we verify things. The phase documents in [phases/](phases/) define
*what* must be verified for each task. Every task in a phase doc has a **Verify** block; a task is
only done when every item in that block passes.

---

## 1. Test levels

| Level | Tool | Where | What it covers |
|---|---|---|---|
| Unit | `cargo test` | `#[cfg(test)] mod tests` next to code | Single functions: name encoding, date parsing, one edit op |
| Table-driven | `cargo test` + `rstest` | same | Many input → expected output pairs (inline syntax, tags, link normalisation, query parsing) |
| Snapshot | `insta` (+ `cargo insta review`) | `crates/*/tests/snapshots/` | Parsed tree / AST / SQL output of fixture files; diffs shown on change |
| Golden files | custom harness | `fixtures/` | Edit ops: `before.md` + `op.json` → `after.md`, byte-exact |
| Property | `proptest` | `crates/*/tests/prop_*.rs` | Invariants over random input: round-trip fidelity, no panics, spans valid |
| Fuzz (optional) | `cargo-fuzz` | `fuzz/` | Parser robustness on arbitrary bytes, run for long sessions |
| Integration | `cargo test` + `tempfile` | `crates/{index,graph}/tests/` | Index + graph service on real temp directories, watcher, atomic writes |
| Benchmark | `criterion` | `crates/*/benches/` | NF-1…NF-6 targets on the synthetic graph |
| UI unit | Vitest | `ui/src/**/*.test.ts` | Stores, keyboard command logic, view components |
| UI in browser | Playwright | `ui/tests/` | UI running in Chromium against the **real Rust backend** through `notatnik-dev-server` (see §4) |
| End-to-end | WebdriverIO + `tauri-driver` | `e2e/` | The real Tauri app on Linux: type in the UI, assert the file on disk |
| CalDAV integration | Radicale (local CalDAV server) | `crates/caldav/tests/` | Sync engine against a real CalDAV server, automated |
| Compatibility (manual) | Nextcloud in Docker + real clients | manual checklists | Nextcloud quirks, Thunderbird, DAVx⁵, Tasks.org |
| Manual acceptance | checklists in phase docs | `docs/phases/*.md` | Things that need a human: feel, UX, real-device behaviour |

## 2. Fixtures

```
fixtures/
├── graphs/
│   ├── basic/          # small realistic graph: journals, pages, links, tasks
│   ├── edge-cases/     # parser torture tests (CRLF, BOM, tabs, broken YAML, code fences…)
│   ├── namespaces/     # deep namespaces, virtual parents, encoded names
│   ├── refs/           # block refs, embeds, aliases, backlinks
│   ├── tasks/          # all task states, dates, priorities, repeats
│   ├── queries/        # graph + queries/*.query + expected/*.json
│   └── ai-eval/        # phase 7: graph + questions.json with expected sources
└── edits/
    └── <op>/<case>/{before.md, op.json, after.md}
```

Rules:

- Fixtures are hand-written, small and readable. Each graph has a `README.md` saying what it covers.
- Expected outputs are either insta snapshots (reviewed by a human when they change) or explicit
  `expected.json` files (for things with exact, hand-verified answers like query results).
- A snapshot change in a PR must be reviewed; never blindly accept with `cargo insta accept`.

## 3. Synthetic graph (performance)

Generated by `notatnik dev gen-graph --seed <n> --pages 10000 --out <dir>` (phase 1, task P1.38).

- Deterministic: same seed → byte-identical output.
- Realistic shape: 2 years of journals, namespaces up to depth 5, ~20 blocks per page average with a
  long tail (some pages with 2,000 blocks), links following a power-law distribution, ~15% tasks,
  properties, Polish diacritics in text and page names.
- Never committed. Generated into `target/synthetic/`.

Benchmark results are recorded in `docs/benchmarks.md` with date, commit and machine description.

## 4. Browser tests run against the real backend

The UI talks to the backend only through a generated, typed API module (`ui/src/lib/api/`) with two implementations:

- `tauri`: `invoke('invoke_api', ...)` calls (the app).
- `http`: `POST /api/<command>` plus one shared long-poll for events, against `notatnik-dev-server` (tests and
  `pnpm dev`). Decision D21.

Every Playwright test starts its own `notatnik-dev-server` on a temporary copy of a fixture graph (`ui/tests/fixtures.ts`:
`backend.write/read/exists/open`), so a test asserts the **file on disk** after a UI action and no mock can drift from the
real behaviour. A few true end-to-end tests with the real window (WebdriverIO + `tauri-driver`, needs the
`webkit2gtk-driver` apt package) are still open.

Things that bit us, worth knowing when writing a test:

- Scope locators to what you mean. A page can show the same block twice (the *Tasks* section lists tasks that are also in
  the outline, the *Recent* list and the sidebar have buttons named like others), so use
  `page.getByRole('tree', { name: 'Blocks' })`, test ids and `exact` names.
- Playwright counts `opacity: 0` as visible. Assert the computed style when "is it really shown" matters
  (`getComputedStyle(el).opacity`), as `props.spec.ts` does.
- CodeMirror ignores accepting a completion within 75 ms of the popup opening: wait ~150 ms before pressing Enter.
- Playwright's mouse cannot press the back/forward buttons: dispatch the DOM events (`mouse.spec.ts`).
- Never build another checkout into this repo's `target/` (stale `notatnik-dev-server`, see `docs/TODO.md`).
- A test that is flaky 1 in 10 is a bug until proven otherwise: the selection/commit races were real data-safety bugs.

## 5. The check script

`scripts/check.sh` is the single command that must pass before any commit. It grows with the project:

| Since | Step |
|---|---|
| Phase 0 | `cargo fmt --all --check` |
| Phase 0 | `cargo clippy --workspace --all-targets -- -D warnings` |
| Phase 0 | `cargo test --workspace` |
| Phase 0 | `cargo check -p notatnik-core --target wasm32-unknown-unknown` |
| Phase 1 | `wasm-pack build crates/core-wasm` + Node smoke test |
| Phase 2 | `pnpm -C ui lint && pnpm -C ui check && pnpm -C ui test` |
| Phase 2 | Regenerate IPC bindings (`scripts/gen-bindings.sh`); the `bindings_are_up_to_date` test fails if they are stale |
| Phase 4 | `cargo test -p notatnik-caldav --features integration --test radicale`: the contract and engine checks of `crates/caldav/tests/common` against Radicale. It uses a running one if `RADICALE_URL`, `RADICALE_USER` and `RADICALE_PASSWORD` are set, else starts `radicale` (or the Python of `uvx --from radicale`) on a free port with a temporary folder and stops it afterwards; with neither it skips. The same checks run on the in-memory server in `fake_contract.rs`. |
| Phase 4 | `cargo test -p notatnik-app --test nextcloud -- --ignored` and `cargo run -p notatnik-caldav --example live`: a real Nextcloud (`NC_SERVER`, `NC_USER`, `NC_PASSWORD`, `NC_CALENDAR`), by hand; `dev/nextcloud/setup.sh` starts a throwaway one and prints the login |
| Phase 2 | Playwright against the real backend (`ui/tests/*.spec.ts`, `retries: 2`) |

Slow suites (benchmarks, `tauri-driver` e2e, Radicale integration, fuzzing) run via
`scripts/check.sh --full`.

## 6. Manual acceptance checklists

Each phase doc ends with a manual checklist. Run it before marking the phase done, and record in the
phase doc the date, the commit and anything that failed. Things a human checks: does editing *feel*
instant, do keyboard flows work without thinking, does the app survive a real Nextcloud sync,
does it behave on a real Android phone.

## 7. Data-safety tests (always required)

Because the app edits the user's only copy of their notes, these invariants have dedicated tests and
must never regress:

1. **No-op fidelity:** parse + serialize with no edits produces byte-identical output, for every fixture and the synthetic graph.
2. **Locality:** an edit to block B changes no bytes outside B's span (plus the span of its neighbours, for structural ops).
3. **No clobber:** a write whose base hash doesn't match the file on disk is refused.
4. **Atomicity:** a crash at any point during a write leaves either the old or the new file, never a partial one.
5. **No silent deletion:** sync logic (file sync, CalDAV) never deletes user content without either an explicit user action or a recoverable copy.
6. **Backups round-trip and stay outside:** a snapshot restores byte for byte (all files but `.notatnik/tmp/`), is refused
   inside the graph folder, never leaves a `.partial` file, and replacing a page from a snapshot first saves the version
   it replaces (BK-1..BK-10 and EN-2..EN-6 (sealed snapshots hold no marker string, lock and unlock by password and recovery key, never plain, conversion, `notatnik decrypt`), including the comparison with the current state, stored vs deflated entries, the device files, the second folder and the settings preview; `crates/graph/tests/graph.rs`, `crates/app/tests/app.rs`, `ui/tests/backup.spec.ts`).
7. **Interrupted operations are undone:** a journal record left by a rename or delete that stopped half way is rolled back on
   open (files byte for byte as before), a completed one is only dropped, and a normal operation leaves no record
   (`crates/graph/tests/graph.rs`: `a_rename_that_died_half_way...`, `a_delete_that_died_half_way...`).
8. **Page history never loses a replaced text:** restoring a version, or a write from outside, leaves the text it replaced
   as a version (`a_restore_right_after_an_edit_keeps_the_text_it_replaces`, `ui/tests/history.spec.ts`).

## WebKit (the desktop app's engine)

The browser tests in `scripts/check.sh` run in Chrome, but the desktop app runs in WebKitGTK, which differs in details
that matter for editing: it takes the focus away from a moved row without raising an event, so Alt+↑/↓ used to stop
after one move there while Chrome was fine. `scripts/check-webkit.sh` runs the files in `ui/tests/webkit.list` (editing,
selection, moves) in Playwright's WebKit build (`ui/playwright.webkit.config.ts`; the first run downloads it, about
100 MB). Run it after changes to the editor, focus handling or keys. The whole suite also runs there
(`npx playwright test -c playwright.webkit.config.ts`): all but one test in `navigation.spec.ts` (clipboard) pass.

## Sync with a server

The sync engine and the app are tested against `notatnik-sync`'s in-memory WebDAV server (`fakedav` feature; the
browser tests start its binary `notatnik-fakedav`). Runs against a real Nextcloud are `#[ignore]` tests that read
the server and login from environment variables and clean up after themselves; see [webdav.md](webdav.md).
